# Runtime 优化修复设计

## 目标与边界

- 缩减控制面工作项对 Git 基线、`doctor`/`check` 输出和持久状态的放大效应，同时保留真实产品变更语义。
- 允许 `ANALYSIS` 在 `ANALYZING` 阶段通过 `harness run` 执行策略判定为 `allow` 的命令，并把成功命令 ID 绑定到分析结论。
- 缩短测试反馈路径，避免 benchmark 新测试因硬编码清单而漏跑，并为本地测试入口及 CI 设置明确超时。
- 修复重复 ADR 编号。
- 不恢复模型实验，不修改既有历史工作项，不改变开发型工作项的验证契约。

## Runtime 契约

### Git 基线与健康摘要

`getGitBaseline` 增加可选的路径排除与指纹开关；默认行为保持不变。新工作项基线排除配置的 `workItemsDirectory`，不读取其内容指纹，并继续以已保存的源码快照作为交付范围依据。

`doctor` 仍报告整个 Git 工作树是否 dirty 以及完整变更数量，但 `changedFiles` 只返回固定上限的排序预览，并显式返回省略数量。这样保留诊断含义，同时让机器输出有界。

### ANALYSIS 命令证据

开发型 `run` 保持原计划、任务和阶段约束。仅当工作项为 `ANALYSIS` 且状态为 `ANALYZING` 时，允许无计划、无任务、无 check ID 的命令：

1. 命令先经现有 deny-first 策略判定，再经 ANALYSIS 专用只读白名单；只允许平台真实 Node 的版本查询、`node --check` 和精确标准相对入口的 Runtime 只读子命令。Node 身份与脚本路径按 Windows/POSIX 各自规则比较；测试、构建、格式化、伪装脚本、配置追加 executable 及其他可执行项目代码的命令在 ANALYSIS 中拒绝。
2. 命令前后保存源码快照；退出失败、超时、输出失败或源码变化均记录为失败。
3. 分析命令不携带计划摘要或计划检查映射，不触发开发任务结果失效逻辑。
4. `analysis-add --command <ID>` 可重复使用；非 `UNKNOWN` 结论可由文本证据、成功命令证据或两者共同支撑。
5. 写入结论和 `check` 都验证命令归属、状态、修订、ANALYSIS 只读策略、退出结果、当前源码快照及同命令后续失败，防止伪造或陈旧引用。

旧分析结论没有 `commands` 字段时继续合法。

## 测试与 CI

- 默认测试项目在每个 Node test worker 内建立一次已安装 Git 种子；不测试安装/初始化差异的默认夹具从种子复制，特殊模式继续走原始安装路径。每个测试仍获得独立目录和独立 `.git`，退出时仅清理已验证位于系统临时目录的种子。
- 新增 benchmark 测试发现入口，README 与 CI 只引用该入口；入口和 Runtime 测试入口均设置 10 分钟进程上限并显式报告启动/超时错误。
- GitHub job 设置 15 分钟上限；Ubuntu Runtime 和 benchmark 覆盖 Node 20 与 22，Windows 保留 Node 20 的 benchmark 与 Runtime 覆盖。

## 风险与验证

- Git 摘要截断可能影响依赖完整路径列表的调用方：保留 `changedFiles` 字段并新增总数/省略数，源码快照和范围检查仍使用完整集合。
- ANALYSIS 不执行测试、构建或格式化等可运行项目代码的命令；前后源码快照比较继续作为纵深校验，但不被描述成防止外部副作用的沙箱。
- 夹具复用可能造成测试间污染：每次复制完整种子，并用隔离性回归验证两个项目互不影响；安装器自身测试不走缓存。
- doctor 优先预览产品路径并单列控制面数量；guide 不计算未使用的 fingerprints。夹具种子退出清理只针对 realpath 确认的临时目录，使用有界重试，失败输出错误并令测试进程失败。
- 运行聚焦 Runtime 测试、全量 Runtime 测试、benchmark 全量测试、doctor 与 `check --ci`；全局 CI 如仅被既有非终态实验阻塞，必须单独报告。
