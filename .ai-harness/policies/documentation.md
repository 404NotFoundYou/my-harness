# 文档与版本策略

文档保存对后续决策有用的目标、取舍和当前事实，篇幅与任务匹配。Runtime 工作项保存普通任务的方案、计划、验证、审查、验收和证据，普通任务不重复创建版本计划或验证报告。

## 新项目

首个版本默认 `v1.0`，正式编码前建立最小文档基线：

```text
README.md
docs/
  README.md
  product/overview.md
  architecture/overview.md
  architecture/decisions/
  versions/v1.0/
    README.md
    STATE.md
```

数据库、前端和移动端架构文档只在项目实际涉及对应能力时创建。`docs/README.md` 只链接已经创建的文档，不为未使用的能力保留空入口。

版本目录保存本版本目标、范围和面向人的当前状态，并链接稳定事实。`PLAN.md` 和 `VERIFICATION.md` 只在新版本、重大里程碑、外部交付或既有项目规范要求时作为人类可读快照创建。普通任务的计划、验证、审查、验收和证据以 `.ai-harness/work-items/<WORK-ID>/` 为准。

允许预建空模板，但空文档不能作为门禁通过证据。稳定当前事实只维护一份，版本快照不能复制出另一套持续维护的事实。

## 已有项目

- 优先沿用现有目录、命名、版本、Issue、ADR 和发布规范；有等价文档时禁止另建默认结构。
- 未明确要求时不得批量移动、重命名或重建文档结构。
- 明确要求重生成时，先完整读取原文档、代码、配置、Schema/迁移、测试和部署入口，建立“文档结论 -> 代码证据”追踪。
- 当前检出代码、迁移、运行配置和测试是主要证据；旧文档和候选分支只作背景。冲突并列记录，不得编造第三种现状。
- 版本发布后的历史目录不可改写为后续现状；修正必须记录原因、日期和责任人。

每个任务将文档影响写为具体路径或 `N/A: 理由`。`docsImpact` 是计划写入范围声明，不等于必须新建文档。用户可见行为、Schema、API、配置、架构、部署或运维的约定变化同步受影响文档；恢复既定行为且原文档仍正确的 BUG 可以记录不适用，不为完成流程复制一份文档。
