# project-v2 共享记忆控制方案与无模型验收条件

目标：下一轮对照两组具有同一可核验执行环境，宿主项目记忆不再成为额外可读上下文。保持题目、判定、180秒/80工具、模型和评分固定。当前是PROPOSAL，只有CLI开关接受和离线提示预览已经实跑，完整环境隔离未实施。

## 明确选择

对冻结的Codex CLI0.156.0，选用两组一致的--disable memories；本机features list确认true→false。这个总开关比同时加入未逐项实测的记忆细分键更简单。保留原--ephemeral，但它的会话存储语义不能代替记忆或文件访问控制；不改变用户默认配置，不删除或改写共享记忆。

仅把CODEX_HOME指向新目录仍不能阻止模型shell按已知绝对路径读取原目录；仅禁用记忆也不能保证不被shell手工读取。因此下一轮采用有实际文件读取限制的独立执行环境，排除宿主记忆路径，保留工作区和必要运行依赖的访问。不要把提示中“别读记忆”当作访问控制。

## 终态观察的最小补充范围

目标候选为benchmarks/codex-driver.mjs及其计时/审计直接调用方；另建开发型工作项，先读严格schema和版本校验。只增加可观测事实，不改变completedRun或180秒截止口径。

- 在归档final.json被规范化前，保存原文件是否存在、字节数及解析分类（缺失、读取失败、非法JSON、schema不符、有效）。不保存未脱敏原始正文；不能从旧null反推原状态。
- 保存最后assistant消息、有效最终响应、turn.completed的接收时间，必要时由客户端明确的请求边界支持归因。没有请求记录时继续标UNKNOWN，不把无日志间隔称作模型纯推理或网络耗时。
- 用模拟CLI分别生成“有效终态”“缺文件”“非法JSON”“schema不符”“完成工具后预算终止”记录，验证观测字段与现有完成评分相互独立；无真实模型调用。

隔离和观测通过前不提出追加付费会话；正式复测仍按独立费用授权及新的冻结配置执行，失败超时全部保留，不追加补跑。完整环境变化后的结果作为新实验，不能据此改写旧失败或声称已控制所有模型/网络变化。
