# 非原生跨平台移动端策略

- 适用于 Flutter、React Native、KMP、MAUI、Ionic/Capacitor 等共享代码方案；目标平台未明确时至少评估 iOS 与 Android。
- 编写公共接口、桥接或平台相关 API 前，明确目标平台、最低系统、设备、商店/签名和测试环境。
- 计划建立能力矩阵：统一业务语义、各端可实现性、权限/系统限制、依赖、配置、批准差异、错误和逐端验证。
- 共享接口统一输入、输出、错误、取消、超时、权限拒绝、生命周期和幂等；平台差异封装在适配层，不在业务层散落分支。
- 禁止空值、永远成功、吞错或无操作实现伪装平台支持；后端核心契约保持平台中立。
- 任一目标平台无法实现或业务语义不一致时立即阻塞受影响任务并询问；不得只适配当前可运行端。其他独立任务继续。
- 每个平台分别验证依赖解析、静态检查、构建、权限、成功/拒绝/取消/失败、生命周期与恢复；单端、Mock 或共享测试通过不能代表多端完成。
- 配置、权限、Entitlement、Manifest、签名和凭据按平台与环境隔离，开发/测试标识不得泄漏到生产。
