# 前端与 Figma 策略

- 项目现有框架、设计系统、组件库和令牌优先；禁止暗建第二套 UI 范式。
- 新增/修改可视 UI 默认需要批准的 Figma 节点；明确不使用 Figma或已有项目以当前界面/设计系统为基线时记录不适用依据。
- 编码前读取节点设计上下文、组件/Variant、变量和 Code Connect；截图用于验证，不能在节点数据可用时替代设计上下文。
- 权威边界分开：PRD 决定业务规则，API/Schema 决定数据契约，Figma 决定视觉/交互表达，代码库决定实现范式。冲突必须暴露。
- Figma 参考代码不能直接粘贴；先复用现有组件和令牌，建立节点到验收、路由/权限、API、代码、视口和证据的映射。
- 完成核心用户流及加载、空、成功、失败、无权限、超时、禁用和重试等适用状态；前端校验不能替代服务端权限和业务校验。
- 支持窄/中/宽视口或目标设备，验证长文本、字体缩放、键盘、焦点、屏幕阅读器、颜色对比和替代输入。
- 防止瀑布请求、重复请求、无界列表、主线程长任务、布局抖动和不必要重渲染；输入、富文本、URL 和文件按信任边界处理。
- UI 验收必须在正式运行入口、相同 Frame/视口、字体、资源、主题和数据状态下截图对比；业务逻辑和视觉还原分别报告。不能用构建成功或单张默认态截图替代真实界面验证。
