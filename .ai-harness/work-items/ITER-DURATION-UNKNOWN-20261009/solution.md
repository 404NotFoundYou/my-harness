# 缺失时长汇总口径与历史审计兼容

现状：`summarize` 的组总时长把缺失样本按 0 累加，而 `trialStatistics.latency` 将同一样本计为 unknown；`executionSummary` 写出 groups，`auditExperiment` 严格重算并比较归档摘要。历史协议 v1-v4 没有摘要口径标识。当前 19 份已跟踪试次结果均有 durationMs，但不能据此推断外部/未跟踪归档的完整性。

方案：新建 v4 实验在冻结 protocol 和 summary 都标注 `summaryVersion: 2`。新口径组总时长：只有全部样本耗时是非负有限数时求和，否则为 null；真实 0 仍是 0。旧协议缺标识时保留原来的缺失按 0 聚合口径，仅用于审计旧记录；校验未知标识、协议/摘要标识不一致，不能仅删除新摘要标识来降级审计。`experimentPlan`、模型预算、历史文件、判定器和单试次度量不变。v4 的恢复检查兼容旧冻结协议结构；旧源码哈希门禁仍生效。

验证：先让现有含缺失耗时的测试对组总量断言失败，再验证新口径（缺失、0、有值）、模拟新协议的完整执行/审计、旧版本归档审计及协议/摘要标识不一致的拒绝。目标测试和全量 benchmark 框架测试均需真实执行；CI 若因既有 BLOCKED 工作项失败则明确报告，不改变该实验状态。

无数据库：仅本地 JSON 实验证据的生成和审计，无数据库 Schema、查询、事务或生产数据影响。风险：摘要 JSON 契约扩展、历史审计兼容；在明确版本门禁之外不接受静默放宽。
