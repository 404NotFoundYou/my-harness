# 安全与权限策略

- 默认允许仓库内只读检查和任务范围内可逆编辑；`ANALYSIS` 仅允许控制面状态写入，不得改产品文件。
- 删除、覆盖、历史重写、强制推送、生产数据、部署、发布、费用、外部消息、凭据和账号变更必须有明确授权。
- 测试/构建命令优先使用 `harness run`；先由 deny-first 策略判定，`ask`/`deny` 均不会执行。禁止为了绕过判定改用嵌套 shell。
- Runtime 之外的宿主工具仍受 AI 客户端权限和沙箱约束；不得以 runtime 未能拦截为授权。CI 必须执行 `harness check --ci` 兜底。
- 破坏性动作前以只读方式解析精确目标；禁止对仓库根、用户目录、未解析变量、符号链接或联接目标做递归写入/删除。
- 不覆盖或回退用户/其他 AI 的既有变更；基线冲突无法安全合并时停止。
- 密钥、令牌、个人数据和生产敏感信息不得进入源码、状态、证据、测试、日志或最终回复。
- 新依赖必须证明现有能力不足，核实维护状态、版本、许可证、安全风险、安装脚本和锁文件影响；依赖安装属于 `ask` 操作。
- 网络事实记录来源和访问时间；会漂移的关键事实在决策前重新验证。
