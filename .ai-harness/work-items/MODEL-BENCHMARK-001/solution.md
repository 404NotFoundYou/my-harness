# 固定任务模型对照

沿用 reliability 工作项中的 benchmark-design.md：三个固定小项目、三组相同公开规格与预算，独立临时 Git 工作区。实现位于根 benchmarks/，不进入 installer 的 .ai-harness 载荷。Codex CLI 驱动复用已有登录，输出参数数组、临时会话、workspace-write 沙箱；模拟驱动只用于框架测试。输入固定、时间/工具上限与顺序由代码维护，不交给模型判断。

公开任务文件与隐藏验收分离。模型结束后仅复制允许的实现到新的判定目录，判定必须有完成标记和完整用例结果，不能只看退出0。记录实际模型ID、源码/任务哈希、CLI用量、耗时、调用数、超时、所有失败、文件范围和Harness状态。保留逐项产物和自报完成与独立通过的差异。先运行一次九样本先导；只依据开发集失败补必要上下文/验证辅助，再按同一固定输入与预算复验三组，留出题不参与调整。

辅助优先复用现有guide和计划检查；若真实失败暴露读取缺口，可给guide增加可选的有界上下文读取，读取明确文件与本地直接调用方/导入，不新增门禁或自动判断通过。数据仅为生成的本地实验产物，不修改Runtime状态/Schema、应用数据库或用户登录配置；无数据库影响。结果说明小样本和自定义服务模型身份边界，不以token声称货币费用，不承诺模型能力等价。

验证覆盖判定器拒绝提前exit0、不完整结果、越界改动，隐藏内容不进入参与者项目，三组预算/输入一致，真实与模拟结果隔离。Runtime受影响测试和benchmark框架测试均需通过；真实试跑属于用户已授权的独立实验，超过Runtime单命令120秒上限，由本机CLI执行后通过CLI登记实际证据。
