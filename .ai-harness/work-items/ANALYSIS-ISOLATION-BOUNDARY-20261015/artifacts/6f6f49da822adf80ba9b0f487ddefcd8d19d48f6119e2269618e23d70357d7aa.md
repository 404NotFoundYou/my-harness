# 剩余文件访问隔离的具体方案

当前应保留原预检 ready=false。记忆开关已在固定 CLI 的本地模拟请求中取得正反对照；下一步验证独立执行环境的文件可见性。

需要先由用户启动已安装的 Docker Desktop，使 Linux daemon 可连接。自动审批拒绝了本轮 docker desktop start --help，不能用其他启动入口规避。启动后先只读确认 daemon、现有镜像和固定 CLI 的可用性；本方案不包含安装、升级、镜像拉取或迁移凭据。

在现有可用环境中创建一次性容器，仅挂载本轮临时测试工作区和合成 CODEX_HOME，不挂载宿主用户目录、真实 .codex 或真实记忆。模型端继续用本地固定响应器，不连接真实 provider。容器网络与响应器的连接方式需按实际环境确认，不能把 Windows 宿主的 127.0.0.1 直接当作容器的同一地址。

用随机合成文件建立宿主可读正对照；对工作区内、工作区外、合成宿主记忆路径逐一验证，并记录路径映射、镜像/CLI 身份和实际失败码。先证明文件在宿主存在，再判断容器内不可达；不能把缺失的正对照或程序未执行算作拒读。通过实际会使用的执行工具复验，外部 MCP 不继承结论。

只有这些实际结果成立、环境输入稳定且记忆控制仍有效，才能讨论后续预检集成。任何执行器未覆盖、环境缺失或失败继续保留为未验证；真实模型复测另行冻结预算后再执行。本文件是待执行方案，未运行任何容器命令或修复真实文件访问权限。
