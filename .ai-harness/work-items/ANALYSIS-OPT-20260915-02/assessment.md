## 已复现问题

### P1：安装收据还会受到 Git 换行转换影响

**PROVEN。** 现有 [Git 属性](../../.gitattributes) 保护 `work-items/**`。安装收据覆盖的范围还包括 Runtime 自身及标准 CI 文件，[安装器](../../src/installer.mjs:478) 按实际字节记录哈希，[卸载预检](../../src/installer.mjs:628) 逐项核对源与目标。

隔离复现步骤：从当前提交建立自动 CRLF 的源克隆，安装到空目标项目；卸载只读预检无冲突。将目标提交到 Git，再以 `core.autocrlf=false` 建立全新检出，对新检出执行同一源版本的卸载预检。

结果：冲突从 **0 项变为 87 项，87 项都只有 LF/CRLF 差异**。测试发生在 Windows，第二种 Git 配置模拟 LF 检出，不是本轮 Linux 实跑。没有执行卸载删除。

**PROPOSAL。** 把安装载荷的字节规范和 Git 属性保护纳入安装契约，覆盖所有需要与收据逐字节一致的托管文件；明确安装、提交、跨平台检出和卸载的生命周期。保留真实修改和损坏文件的拒绝逻辑，不通过忽略哈希或强制覆盖解决。

验收：Windows来源安装后经两种 Git 检出配置，重复安装及卸载预检仍无伪冲突；真正改动任一受管文件仍报告冲突；目标项目既有规则与 Git 属性得到保留。

### P1：长日志会中止原本能成功的命令

**PROVEN。** [evidence.mjs](../../src/evidence.mjs:91) 使用 `spawnSync`，执行缓冲区为 `max(maxCapturedOutputBytes × 16, 1 MiB)`。默认预览上限16 KiB，对应实际执行缓冲区1 MiB。

同一个输出约2 MiB日志的 Node 测试，直接运行且提供4 MiB缓冲区时退出码为 **0**；通过 Harness 执行得到 **fail / ENOBUFS**，捕获约1,048,639字节，`timedOut=false`。这不是断言失败，命令被输出缓冲区上限中止；全文 artifact 也只能保存已经捕获的部分。

**PROPOSAL。** 分开“返回模型的预览大小”和“执行过程的输出资源上限”。对正常大输出使用流式读取及有界落盘，保留退出码、完整性标记、字节数与哈希；超出总资源上限时明确报告原因。日志脱敏需保持跨数据块的一致性。

验收：2 MiB正常日志不再触发ENOBUFS，预览仍有界；故意失败的测试不能被大日志掩盖；输出截断、磁盘不足、超时及断言失败能区分；不会无限增长内存或磁盘。
