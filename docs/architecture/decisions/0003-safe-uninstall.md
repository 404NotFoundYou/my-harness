# ADR-0003：卸载 Runtime 时保留审计数据

- 状态：接受
- 日期：2026-08-19

## 背景

Harness 可以无损安装和升级，但缺少对称的卸载入口。直接递归删除 `.ai-harness/` 会同时破坏工作项、证据和历史备份，也无法安全区分项目规则与 Harness 托管规则。

## 决策

提供 `uninstall --target <TARGET>`。命令必须从独立 Harness 源仓库执行，以便与目标文件做可信内容对比；禁止目标项目使用自身 Runtime 自卸载。`--dry-run` 只返回完整操作计划；正式执行还必须显式提供 `--confirm`。

安装时生成 `.ai-harness/install-receipt.json`，以带自校验哈希的结构记录实际 payload 路径/文件哈希，以及托管规则块的创建归属和插入边界。卸载仅处理该收据能确定归属的内容：

- 从 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 移除结构和哈希均有效的 Harness 托管块，保留块外项目内容；仅含托管块的文件可以删除。
- 移除安装收据中记录、且当前独立源和目标内容都与安装哈希一致的 Runtime 文件、标准 CI 文件，以及安装收据自身和 `.ai-harness/project.json`。
- 保留项目文档、业务文件、`.ai-harness/work-items/` 和 `.ai-harness/backups/`。

执行顺序固定为完整预检、目标快照记录、完整备份、备份后全量复核、逐项紧邻复核、应用变更、仅删除空目录。托管块或边界被修改、源/目标 Runtime 内容与收据不符、版本不一致、路径越界或文件类型异常时停止。备份后的目标漂移会清理本次备份并保持目标新内容；应用阶段失败时从本次备份回滚，回滚不完整时保留备份并显式返回其路径。

## 结果

卸载是可恢复的，并且不会把审计数据删除授权隐含在普通卸载中。卸载后 `.ai-harness/` 可能因保留 `work-items/` 和 `backups/` 而继续存在；重新安装和初始化后可继续使用这些历史数据。
