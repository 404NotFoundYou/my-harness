# 项目分析与技术咨询策略

- 默认只读产品代码、Schema、配置和文档；允许 `.ai-harness/work-items` 控制面状态写入，不授权开发计划或实现。
- 先确认项目、模块、分支/提交、工作树和适用环境，再读取入口、调用方、配置、Schema/迁移、测试与文档。
- 当前检出代码、实际生效配置、Schema/迁移、相关测试和本次命令结果是主要证据；旧文档、TODO、Mock、示例、文件名和未合并分支只能作线索。
- 本地代码不能证明生产行为；存在测试不能证明本次通过。没有实际运行时不得声称运行时行为已确认。
- 业务分析按范围追踪角色、入口、权限/数据隔离、流程、状态、校验、计算、异常、实体和上下游。
- 技术方案先说明当前实现和复用边界，再说明目标设计、接入位置、接口/数据、兼容迁移、风险和验证。
- 关键结论标记 `PROVEN`、`INFERRED`、`PROPOSAL` 或 `UNKNOWN` 并提供适用证据；冲突并列展示，不能调和成不存在的实现。
- `ANSWERED` 只表示证据化回答完成，不表示功能已实现、测试通过或可发布。用户要求开发后另建开发型工作项。
