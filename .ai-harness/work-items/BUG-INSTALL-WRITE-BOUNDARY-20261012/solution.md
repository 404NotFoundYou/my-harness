# 安装与初始化目标写入边界

当前默认文档初始化用 `path.join` 直接写模板，`docs` 父目录为链接时会写到仓库外。安装先在规划阶段读取目标，随后按旧计划备份和覆盖；目标文件在这两个阶段之间变化时，备份和最终文件都可能不是批准时的内容。卸载已有目标快照复核，可沿用其失败时保留用户内容的原则。

只修改 `installer.mjs` 和安装测试。初始化预检模板的所有写入路径，拒绝路径组件为符号链接或联接，检查后写入时仍重新验证；保持现有普通文档冲突语义。安装对全部计划目标预检，并在每次实际写入及备份后复核文件类型和原内容；不再把目标变化当成可覆盖的旧版本。发生部分失败时，只有目标仍是本次写入的内容才回滚；若出现并发内容，保留该内容及备份并明确报告回滚未完成。该方案处理可观察到的普通并发保存，不宣称抵御恶意进程在最终检查与文件系统操作之间的极短竞态。

先用临时项目的链接目录和受控备份时编辑建立失败复现，再运行同一测试转绿，覆盖普通初始化、安装、卸载及相关调用方回归。无数据库、公共 API、依赖或线上部署变化。原有文档已经要求不越界及不覆盖用户既有工作，当前事实不另改文档；本文件记录本次修复和边界。

独立复核在最后一次检查之后又复现三处竞态，以上逐文件初始化和先检后删方案不再作为交付方案。返工改为：默认文档只接受全新 `docs` 目录，在私有临时目录完整准备后发布；已有 `docs`（即使内容相同）明确拒绝，用户已授权此兼容调整。安装迁移现有目标到备份后核对实际迁移的字节，发布时使用同盘原子不覆盖操作；回滚先迁移目标到隔离区，再决定恢复旧内容还是保留新编辑。文件系统不支持必要原子操作时明确失败，不退回先检后覆盖。不能将这种实现表述为抵御任意恶意目录替换：Node 标准库没有跨平台的目录句柄相对写入或目录 no-replace 交换接口；临时目录注入和独立复核应覆盖可观察的具体竞态，未覆盖的短窗口作为剩余风险报告。

2026-10-13 根据继续修复授权补齐两条已动态复现的路径：初始化对暂存根及每次暂存文件写入使用统一项目内路径校验；清理不删除并发出现的备份父目录链接。安装回滚只迁移本次确认已经发布的普通目标；发布未成功时出现的对象及非普通目标均留在原路径，原文件备份保留并明确报告回滚不完整。补齐备份目录初始/准备期间链接，以及发布失败/后续失败中的目录、联接保留回归。已有默认 docs 全新目录规则及使用指南保持当前事实。

独立复核另实测：单文件发布后的 finally 清理可能在 written 登记前抛错，造成新建文件漏回滚。返工取消单文件发布后的清理，将暂存文件交由已有事务末尾统一清理；发布返回后立即登记 written，之后任何清理失败均进入能追踪全部已发布文件的回滚。受控 unlink/rm EIO 回归确保 INSTALL_ROLLED_BACK 与全部目标文件不存在相符，不增加状态回调或额外抽象。
