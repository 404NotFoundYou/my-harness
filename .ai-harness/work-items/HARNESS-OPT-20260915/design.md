# 优化实施设计

用户已授权按调研建议优化；沿用 Node 标准库、现有状态机、JSON/JSONL 及客户端分工。产品基线为 1.2.0，兼容增量记为 1.3.0。此前分析目录保留。

## 范围与顺序

1. 评测：Codex 与 Claude/Gemini 使用一致的最终结构和成功条件，保留各自协议解析。异常事件、损坏 JSONL、超时和缺失终态均可观察；正常警告不误判。增加源仓库专用 Windows/Linux CI，不改变安装到消费项目的测试要求。
2. 恢复：新锁使用带随机所有者标识的目录，先在临时目录写入所有者再原子发布。独立复核后改为：释放先整体移走目录再清理；恢复先原子认领特定所有者标记，保持排他后检查完整控制面，再记录事件和释放。这样恢复与释放自身中断仍保留代次，且不误删新锁。要求同机、确定失活和标识匹配；旧文件锁、未知/存活锁保持拒绝。恢复不伪造验证或重跑业务操作；不一致时保留认领锁及原始记录。
3. 上下文和引导：明确文本路径单独有界读取，JS/TS 依赖发现保持局部；过滤、数量、大小、二进制及路径错误给出遗漏原因。保留哈希/脱敏和增量语义。BUGFIX 主建议复用现有 finish 与阶段参数；可选精简 guide 响应，默认输出兼容。
4. 评测能力：增加显式重复次数、双组对照及预先指定预算，原三组九样本默认行为兼容；统计区间、中位数/尾部、协议失败和工具阶段耗时。旧审计协议继续兼容，真实调用仍需单独费用授权。先用模拟驱动验证流程及统计。
5. 验收证据：增加兼容的可选检查到验收映射与本地证据产物引用；校验路径、来源和哈希，旧记录不追溯迁移。映射只证明声明及证据归属，不能自动证明语义覆盖。补运行命令全程的分段时间，原 durationMs 保持语义。

## 持久化与兼容

数据库影响 required 指本地锁格式与可选证据字段，无外部数据库、DDL 或生产迁移。新锁目录明确版本与主机/PID/随机token；只回收可验证的当前代次。旧遗留文件锁不自动回收，清楚提示原格式缺少可信所有者信息。历史工作项、成功/失败证据和安装收据不改写。

检查/证据扩展只对显式使用的新字段生效，旧格式仍按原条件校验；计划签名包含新声明，防止修改后复用旧证据。产物保持只读，本地内容变化会使对应引用失效。源码验证结果仍必须匹配当前修订、尝试和代码快照。

## 验证与审查

单一实施任务 T1，完整计划和高风险独立复核。实现由主 AI 串行维护；独立复核只读，不共享写入。验证运行 Runtime 全量、benchmarks 框架全量、旧两轮审计及差异检查。新增回归覆盖协议异常、真实子进程持锁退出、并发回收/存活拒绝、明确文件遗漏、BUGFIX 阶段、重复评测和证据漂移。发现多文件中断不一致时必须明确拒绝继续，不能宣称自动修复数据。

完成条件为新增场景与旧回归通过、文档同步、实际独立复核通过、工作项 DONE 及 check --ci 成功。Windows/当前 Node 为本次实跑环境；Linux/Node 20 与真实模型收益只在对应实跑后才能宣称已验证。
