# API 与后端契约策略

- 明确调用方、角色/权限、数据隔离、输入输出、状态码/错误码、幂等、超时、取消、分页、排序和一致性语义。
- 服务端鉴权授权是最终边界；客户端隐藏按钮、路由守卫或字段校验不能替代。
- 兼容迭代优先新增可选字段和可并行部署契约；删除、改类型、改语义或收紧校验需版本/迁移窗口和回滚方案。
- 写接口按业务风险提供幂等键、唯一约束或事务保护；禁止重试导致重复扣款、扣减、创建或消息投递。
- 列表分页必须有稳定顺序和游标/页码语义；批量接口设置合理上限并返回可定位的部分失败结果。
- 错误响应对调用方可处理、对日志可诊断且不泄露敏感信息；禁止吞错后返回成功。
- 限流、缓存和重试以真实调用规模和失败模型为依据；重试需退避、上限和幂等保证。
- 使用契约/集成测试验证调用方与服务端；接口变更同步 Schema、客户端模型、文档和兼容测试。
