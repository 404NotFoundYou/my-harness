# ADR-0004：普通任务默认自主推进

- 状态：接受
- 日期：2026-09-14
- 输入：用户要求减少限制模型发挥的流程，并选择“默认自主推进，按任务风险增加流程”。

## 问题与取舍

旧流程把多文件修改和所有 BUG 都映射到逐命令维护的完整状态机，根规则还重复专项策略。模型需要反复填写相同事实，普通任务也承担复杂项目的操作成本。

保留 v1 状态机、持久格式、命令权限和检查器，新增薄编排入口 `begin` / `finish`。不另建轻量状态机，不让模型手写状态，不改变现有命令含义。只读查询和机械编辑仍走原有直接路径；其他普通开发任务保留工作项，避免与已有 CI 写入范围检查冲突。

## 设计

- `begin` 接收权威输入、验收、授权来源、简短方案、数据库无影响证据、写入范围、验证方式、文档影响和 low/medium 风险。支持 ITERATION / BUGFIX；BUG 仍需实际、期望和复现。
- 单 AI、单纵向任务 T1、单 Review Batch R1。方案只保存一次到工作项目录。Runtime 自动检查环境并依次建立基线、方案、数据库判断、计划和 IN_PROGRESS 任务；每一步使用现有 workflow 导出接口。
- 新项目、数据库/API/跨端/多 AI 标志、高风险或 approval-required 授权不适用精简入口。安全、权限、支付、并发等未编码的风险仍由执行者判断并使用完整流程，不能仅凭没有 flag 推定低风险。
- `run` 继续绑定 T1 并记录实际命令。`finish` 必须引用本任务成功的命令证据，且验证命令最新一次执行不能失败；还需明确填写验证结论、差异审查、文档结果、验收结论。
- `finish` 先检查工作项与计划合法性，再通过现有接口依次登记结果和推进状态。同一纵向任务的审查可复用于最终审查，不伪造独立审查。没有新改动、失败或未解疑点时复用已运行的验证。
- 所有步骤串行调用既有 CLI 服务层；中断保留真实中间状态，使用 show 和原有细粒度命令恢复，不自动回滚或重放命令。无需新持久化 Schema 或外部数据库。

## 范围、风险与验证

本次为中风险、单 AI 实现：新增 CLI 编排和使用规则，不修改命令权限、状态合法性、公共服务 API 或安装/卸载语义。范围是 compact 编排模块、CLI 接线、意图测试、根规则及安装模板、受影响指南和本 ADR。

验收覆盖：精简 ITERATION/BUGFIX 完整闭环、原有流程兼容、前置参数错误不遗留工作项、需审批/高风险/数据库拒绝、缺失/失败/过期或其他任务命令证据拒绝、审查及验收缺失拒绝、CI 继续拒绝越界或未完成工作项。执行 Node 内置测试、doctor、git diff --check 和最终 check --ci。

不验证模型升级后的质量或速度提升；命令数与规则长度降低可确定性比较。客户端权限仍由宿主控制，仓库内 Runtime 不是沙箱。

## 规则调整

根契约保留授权、事实、验证及路径选择，把完整命令序列留在使用指南。常规可逆实现选择由 AI 决定，只对影响目标、兼容性、外部副作用或无法安全推断的关键问题询问；当前请求已授权的事项不重复确认。

ADR-0002 的直接路径继续有效；其“所有其他任务必须逐命令执行完整协议”的使用方式由本 ADR 的按风险编排取代。新入口不降低已有工作项的状态与证据门禁。
