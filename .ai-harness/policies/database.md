# 数据库策略

数据库设计必须在正式编码和任务执行计划前完成，但其输入必须包含已确认的业务流程、领域边界、API 以及查询/写入草案。

## 基线与建模

- 新项目明确数据库类型/版本、数据所有权、规模、一致性、租户、备份恢复和保留边界。
- 迭代/BUG 读取实际 Schema、全部迁移、ORM/访问层、关键查询和已部署迁移边界；不能只看模型类或旧文档。
- 建表前梳理过滤、排序、分页、关联、聚合、唯一性、并发、频率和数据量，再推导字段、约束和索引。
- 单表优先：同一业务域、生命周期、权限和一致性边界内能清晰覆盖时不拆表。只有域/生命周期/安全隔离、无界一对多或独立查询约束等结构差异才拆表；禁止用 JSON 隐藏独立实体关系。
- 明确主键、关系、基数、空值、默认、唯一、外键/检查约束和删除行为。金额不用浮点；时间明确 UTC 存储和业务时区。
- 索引来自真实查询路径、选择性和写入成本，并使用代表性数据或查询计划验证。

## 查询、事务与安全

- 禁止 N+1；使用批量查询、预加载、集合查询或 DataLoader，并用查询次数/日志/性能测试证明。
- 批量操作优先；大批量分块控制事务、锁和内存，禁止无界事务。
- 配额、余额、库存、状态转换和任务领取明确事务、隔离、幂等与失败恢复；禁止未保护的先读后写。
- 多租户强制数据边界并测试越权；凭据不入库文件、日志或测试夹具。

## 迁移与验证

- 已执行迁移不可修改、重排或复用编号；变化只能追加。
- 默认 `expand -> migrate/backfill -> contract`，验证新旧版本共存窗口。
- 大表 DDL/回填评估锁、耗时、复制压力和恢复；回填分批、幂等、可重入、可观测。
- 生产数据/破坏性操作需要明确授权、备份恢复和可审查脚本。
- 新项目验证空库初始化；迭代验证从已部署版本升级。未执行的规模、并发或生产验证标记 `未验证`。
