# ADR-0007：验证、交付范围与返工的可靠闭环

- 状态：已采用
- 输入：用户要求修复 assessment.md 中已复现缺陷，然后建立三组真实模型对照。

## 目标与边界

验证必须对应计划中可执行的命令和实际代码版本；代码改变或新失败后不能复用旧通过结论。范围校验覆盖删除、重命名和合法控制面，同时避免历史任务继续授权任意新修改。审查失败可以返回实现，调整计划有版本和授权记录。保留零第三方依赖、无 shell 命令执行及旧证据，不伪造独立复核。

## 模块与流程

- Git/快照层：用 NUL 分隔的 Git 输出枚举文件，包含删除和重命名。代码快照排除 Git 元数据与有效工作项控制面，使用 Git 的文件内容标识及模式，并保存有哈希的快照文件。验证前后都读取快照，执行期间代码变化不算稳定通过。
- 验证层：把 --verify 的明确命令或结构化 JSON 声明编译成命令/参数数组，关联任务与验收。禁止 shell 展开，无法确定解析的描述需要补充可执行声明。run 可按检查 ID 执行，原有透传形式必须匹配计划检查才能作为完成证据。
- 证据层：命令保存检查 ID、计划版本、代码快照、退出码和输出；登记通过和阶段迁移重新核对这些数据。后续失败使相关验证与审查失效，旧证据保留在日志中。
- 范围层：合法工作项控制面独立于产品写入范围。当前工作按其基线与批准范围校验；完成时保存实际交付的文件变化和内容快照，历史完成记录只能证明冻结的版本。已有终态记录从实际 Git 提交确定归档边界，不补造曾经未执行的测试。
- 恢复层：reopen 返回实现并递增修订号，清空当前验证/审查/验收，保留历史；replan 另保存旧计划版本并解除计划锁，重建批准门禁。普通 transition 不得绕过该失效流程。
- 执行层：版本查询只接受明确查询形态。Windows 包管理器解析到已安装的明确 Node CLI 入口，保持 shell:false，不笼统允许 cmd/pwsh。

## 持久化设计

只扩展仓库内 JSON 契约，不使用外部数据库。新增结构化检查、工作项修订号、命令的源快照引用、终态交付收据和计划归档；公开 Schema 与执行校验同步。快照按内容哈希去重，放在所属工作项内，引用需校验路径和内容哈希。旧在途记录须通过显式恢复/重新计划补齐当前契约；旧终态保留原始证据并使用真实提交归档，不宣称具备新的验证保证。

每个通过的流水线阶段及对应事件记录 source、revision、planDigest；命令执行或阶段登记发现版本变化时撤销旧阶段，最终门禁逐阶段复核。相同代码与计划的成功命令可以复用，随后同类命令失败则旧证据不能继续引用。审查失败依据当前修订/任务尝试的证据日志判定，pending 不能掩盖；任务需 REWORK 后新尝试，最终审查需 reopen 后新修订。

交付收据保留全仓 source 用于验证，并以 ownedChanges 记录本项拥有的 path/before/after，baseline 与 baselineAt 表示交付比较起点。范围检查从最早活动基线叠加已交付的归属变更，避免把同工作区其他在途文件视为已交付。DONE 写入前检查所有变更均有当前授权；DONE 后重新打开时将上一交付作为新修订基线，旧收据保留在 revisions。

验证代码指纹不等于证明业务语义，验收映射仍是声明；固定任务对照将由独立测试判定结果。配置、锁文件和测试属于代码快照，忽略文件和外部服务状态须明确边界。

## 验证与审查

将全部已复现反例转为回归：旧证据、无关命令、新失败、删除、历史范围、分析控制面、最终返工、重新计划、version 参数和 Windows npm。再验证中文/空格路径、状态恢复及新旧工作项兼容。真实模型对照另建 ITERATION，复用用户确认的现有 CLI 登录，小规模试跑，不用模拟模型结果冒充真实对照。

本工作涉及命令权限和验收门禁，使用独立高风险审查；实现期间由单 AI 串行维护共享接口和控制面。不可用的验证必须明确记录，不能通过改状态掩盖。
